## 3. خطة النشر الآمن (لا تُنفّذ قبل موافقتك)

النشر = دفع الفرع إلى `main`؛ Workers Builds يبني وينشر تلقائيًا.

**قبل النشر**
1. التأكد أن `origin/main` ما زال `7b9d17e` وأن الفرع امتداد مباشر له (fast-forward، بلا merge commit).
2. تسجيل الإصدار الحالي للرجوع إليه: `95051632` + أسماء الأسرار والـ bindings.
3. اختيار وقت بلا طلبات كثيرة.

**النشر**
4. `git push origin seo/phase1-indexing:main` (fast-forward فقط).
5. متابعة Workers Builds حتى يظهر إصدار جديد بنسبة 100% وبنفس الأسرار والـ bindings.

**التحقق خلال 15 دقيقة**
6. الرئيسية، قسمان، 5 منتجات (منها بخور كنسي فاخر وقنديل نحاس) تعمل وتُشترى.
7. `/sitemap.xml` = 171 منتجًا، `/robots.txt` الجديد، صفحة 404 حقيقية.
8. السلة كزائر، وطلب حقيقي صغير بالكاش يمكن إلغاؤه، ولوحة الإدارة تفتح.
9. Rich Results Test لمنتجين (واحد باختيارات، وميدالية).

**الرجوع (Rollback) — أقل من دقيقة**
- `npx wrangler rollback 95051632-…` يعيد الإصدار السابق فورًا (الأسرار والبيانات لا تتأثر؛ المنتجات في `products-data` لا يمسها النشر).
- بعده `git revert` لنطاق الـ commits على `main` حتى لا يعيد Workers Builds نشرها مع أي دفع لاحق.

**بعد النشر**
- Search Console: إعادة إرسال الـ sitemap، وURL Inspection للصفحات السبع في `docs/SEO-SEARCH-CONSOLE.md`.
